# 架构说明

- `my-harness-ui/server.py`：本地 HTTP 服务、静态资源、项目和阶段接口、工具审批入口。
- `harness.py`：官方 SDK 适配、持久会话、任务与事件处理。四阶段独立 Session；同时只运行一个任务。
- `storage.py`：SQLite 项目、对话、运行记录及状态持久化。
- `research.py`：阶段成果确认、输入版本和交接；上游修改使下游旧成果过期。
- `question_evidence.py`：问题及痛点结构化卡片，基于实际读取结果核对引文与来源。核对粒度为片段，不能证明整篇全文读取完整。
- `project_files.py`：项目文件边界校验、上传下载、完整方案文档读取与本地打开。
- `index.html`、`app.js`、`style.css`：原生前端界面和交互，轮询后端任务状态。
- `markdown.js`、`markdown.css`、`vendor/`：本地 Markdown 渲染与 HTML 清理，远程图片不自动加载，实际存在的项目文件可下载。

研究背景 → 可选问题 → 可选痛点 → 完整方案文档 → 实验验证。每一阶段的追加需求通过原持久会话执行，成果确认通过版本机制交接。方案提交重新读取磁盘文本，不使用浏览器缓存的正文，也不会自动执行实验。

SDK 负责模型、网络读取及执行工具；工作台负责交互、状态和成果交接。本地文档打开使用操作系统关联编辑器。工具执行以官方运行时和用户审批为准，实验代码运行在项目环境中。

应用索引与 SDK 会话保存在应用数据目录，研究文件保存在用户指定工作区。运行环境和个人数据必须独立配置，不能把含密钥的数据目录上传 GitHub。
